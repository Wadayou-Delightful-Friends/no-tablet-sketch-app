# コーディングスタイル

読み手が最短時間で理解できるコードを書く。コードは書く時間より読まれる時間の方が
長いので、書き手の手間より読み手の理解時間を優先する。

## 命名

長さより情報量。名前だけで用途・役割が推測できるかを判断基準にする。

- 多少長くなっても、用途が具体的にわかる名前を選ぶ
  - 良い例：`controller_id`（どの実体の ID か名前でわかる）
  - 悪い例：`id`（何の ID か、使う場所まで読まないとわからない）
- 誤解されない名前かを自問する。読んだ人が別の意味に取れる名前は避ける
  - 例：構造が同じでも座標系が違うなら `ScreenPoint` / `WorldPoint` のように分ける
- スコープが数行のループ変数など、文脈が自明な場合だけ短い名前を許容する

## リーダブルコードの判断基準

- コメントは「何をしているか」ではなく「なぜそうしたか」を書く。
  コードを読めばわかることをコメントで繰り返さない
- 条件式は肯定形・単純に保つ。複雑な式は意味のわかる名前の説明変数に分ける
- 一度に 1 つのことをする。関数・ブロックに複数の責務を混ぜない
- 迷ったら「初見の人がこのコードを読んで、意図を取り違えないか」で判断する

## ドキュメンテーションコメント

関数やモジュールごとにドキュメンテーションコメントを書く

- 内容は次を含むこと
  - 概要
  - 目的
  - 使う場面の説明
  - 処理フロー
  - 引数の説明
  - 戻り値の説明
