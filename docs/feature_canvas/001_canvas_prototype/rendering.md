# 描画 — Canvas2D で全消し→全再描画（immediate mode）

## 決めたこと

`infra/render-canvas2d/canvas2d_renderer.ts` は `render(scene)` が呼ばれるたびに

1. `clearRect` でキャンバス全体を消す
2. スタックのストロークを下から順に、world→screen 変換しながら全部描き直す

という **immediate mode（毎回全再描画）** にした。

## なぜ全再描画か（代替案との比較）

全再描画（採用）:

- メリット:
  - 実装が最も単純で、状態は Scene だけ。「Scene を渡せば必ず正しい絵になる」
    という保証が崩れない
  - パン・ズームでは画面の全ピクセルが変わるため、無限キャンバスでは
    どのみち全再描画になる場面が多い
- デメリット:
  - ストローク数・点数に比例して 1 フレームのコストが増える。
    数千ストローク級になるとフレーム落ちしうる

差分描画（不採用。書き込み中の線だけ前回の絵に重ね描きする）:

- メリット: 描いている間の 1 フレームが軽い
- デメリット: パン・ズームでは結局全再描画が必要になり、経路が 2 本に増える。
  「前回の絵」という隠れた状態を持つため、描き漏れ・二重描きのバグが入りやすい

オフスクリーンキャッシュ（不採用。確定済みストロークを別キャンバスに焼き込む）:

- メリット: 確定分の再描画が 1 回の drawImage で済む
- デメリット: ズーム時にキャッシュの再生成が必要で管理が複雑。拡大でぼやける

**判断根拠**: まず正しく動く最小構成を選ぶ。性能が問題になったら、Renderer が
port で分離されているので、infra 側だけをキャッシュ方式に差し替えられる
（domain は変更不要。この分離が効く場面については ports-and-adapters.md）。

## 描画の詳細な選択

- **1 点だけのストロークはドット（arc の塗り）で描く**
  クリックしただけの入力は線分にならず `stroke()` では何も出ないため
- **線幅 = `radius * 2 * scale`**
  radius はワールド単位で保持しているので、ズームに合わせて見た目の太さも変わる。
  「拡大したら線も太く見える」= 紙に描いた絵を拡大するのと同じ直感に合わせた
- **`lineCap` / `lineJoin` = round**
  点列を折れ線で繋ぐため、角張りを丸めて手描きの見た目に近づける
